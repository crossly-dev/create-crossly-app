# __APP_NAME__

A Next.js (App Router) storefront for your [Crossly](https://crossly.net) shop. It shows your active listings with a
buy button on each, using [`@crossly/embed`](https://github.com/crossly-dev/crossly-embed) and a **publishable key**.
Checkout is hosted by Crossly, so card details never touch this site and it stays out of PCI scope.

## Run it

```sh
__PM_INSTALL__
cp .env.example .env.local   # set NEXT_PUBLIC_CROSSLY_PK=crossly_pk_live_…
__PM_DEV__                   # http://localhost:3000
```

Get the key in Crossly under **Settings → Embeds** (or `POST /v1/embeds/keys` with the API). Optionally restrict it to
your domains there. A publishable key is designed to be public: it reads your own active listings and starts a
checkout, nothing else. **Never** use a personal access token (`crossly_pat_…`) in a web page; the app refuses one.

## Gotchas

- **`@crossly/embed` is client-only.** It defines custom elements (`class extends HTMLElement`) when imported, which
  throws during server rendering. The wrappers import it inside `useEffect`; server code (`lib/catalog.ts`) imports only
  its types. Keep it that way.
- **Money is integer cents** (`priceCents: 4599`). There are no float dollars in the embed API.
- **Checkout target.** The button navigates in the same tab by default; a new tab is often blocked on mobile because
  the click is one network request away from the user gesture.
- **Events.** The elements dispatch `crossly:loaded`, `crossly:error` and a cancelable `crossly:checkout` (with
  `detail.checkoutUrl`) on `document`, for analytics or your own routing.
- **Styling.** The elements render in a shadow root; theme them with `--crossly-accent`, `--crossly-radius`,
  `--crossly-min-col`, `--crossly-card-bg` and `::part(card|title|price|image|button)`.

## Deploy

Any Next.js host (Vercel, Netlify, Cloudflare, a Node server). Set `NEXT_PUBLIC_CROSSLY_PK` in the host's
environment; it is inlined into the client bundle at build time, which is fine for a publishable key.
