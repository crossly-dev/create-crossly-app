# __APP_NAME__

A small [Crossly](https://crossly.net) seller bot on [`@crossly/sdk`](https://github.com/crossly-dev/crossly-sdk):

- **Sale alerts.** Every few minutes it reads `GET /v1/sales` and posts each new sale (platform, item, price, fee,
  profit) to a Slack or Discord incoming webhook.
- **Scheduled price drop.** Once a day it pages through your active listings (`GET /v1/listings?status=active`),
  picks the ones that have not changed for N days, and lowers their price by a percentage with
  `PATCH /v1/listings/{id}` `{ "changes": { "price": … } }`, which Crossly pushes to every marketplace the listing is
  live on. It never goes below your per-listing floor or a minimum you set, and it starts in **dry-run** mode.

## Run it

```sh
__PM_INSTALL__
cp .env.example .env      # set CROSSLY_PAT and NOTIFY_WEBHOOK_URL
__PM_START__
```

1. **Token.** Crossly → **Settings → API & webhooks → Create token** with `sales:read` and `listings:read`, plus
   `listings:write` if the price drop should change prices. A token missing a scope gets a `403 insufficient_scope`
   naming the scope it needs.
2. **Where alerts go.** A [Slack incoming webhook](https://api.slack.com/messaging/webhooks) or a
   [Discord channel webhook](https://support.discord.com/hc/en-us/articles/228383668) URL. Leave it empty to print to
   the console.
3. **Price drop.** Read the dry-run report it posts, then set `PRICE_DROP_DRY_RUN=false`.

The first run records the sales you already have without posting them, so you do not get your whole history at once.
State lives in `.crossly-bot-state.json`; delete it to start over.

## Settings

| Variable | Default | |
|---|---|---|
| `CROSSLY_PAT` | (required) | Personal access token, `crossly_pat_…`. |
| `NOTIFY_WEBHOOK_URL` | console | Slack or Discord incoming-webhook URL (https). |
| `SALES_INTERVAL_MINUTES` | `5` | How often to check for sales. |
| `PRICE_DROP_ENABLED` | `true` | |
| `PRICE_DROP_PERCENT` | `10` | Percent off per drop (1-50). |
| `PRICE_DROP_STALE_DAYS` | `14` | Unchanged for this long = stale. A drop updates the listing, so the next drop on it comes 14 days later. |
| `PRICE_DROP_MIN_PRICE` | `5` | Dollar minimum. The listing's own floor (`priceFloorCents`) also applies. |
| `PRICE_DROP_HOUR_UTC` | `15` | Hour the daily run happens. |
| `PRICE_DROP_MAX_PER_RUN` | `25` | Oldest first. |
| `PRICE_DROP_DRY_RUN` | `true` | Report only. |

Listings with a **net** payout floor (`floorIsNet`) are skipped: what they may be listed at depends on each
marketplace's fees, which Crossly's own repricing rules (Automation in the dashboard) already account for.

## Running on a schedule instead

`__PM_START__` stays running. For cron, GitHub Actions or a scheduled container, run the one-shot commands:

```sh
__PM_RUN__ sales         # check for new sales once
__PM_RUN__ price-drop    # run the price drop now
```

Keep `.crossly-bot-state.json` between runs (a volume, or a cache in CI), or every run counts as the first one.

## Notes

- Money on `/v1/sales` and `/v1/listings` rows is decimal-dollar strings (`"84.00"`).
- Each price change sends an `Idempotency-Key`, so a crash and retry on the same day cannot drop a listing twice.
- Crossly can also push sales to you as webhooks (`sale.detected`) instead of you polling: see the
  `webhook-express` template, `npx create-crossly-app --template webhook-express`.
