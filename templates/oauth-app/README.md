# __APP_NAME__

A minimal third-party app that does **Sign in with Crossly**: OAuth 2.0 authorization code flow with PKCE against
Crossly's authorization server at `https://crossly.net/atlas`, then calls the Crossly API for the seller who signed in.
No framework and no OAuth library: [`src/oauth.ts`](src/oauth.ts) is the whole protocol, in about 200 lines you can
read.

## Run it

1. In Crossly, open **Settings → API & webhooks → OAuth apps** and register an app. Add the redirect URI
   `http://localhost:3000/callback`. Copy the client id, and the client secret if it is a confidential app (shown once).
2. Then:

   ```sh
   __PM_INSTALL__
   cp .env.example .env    # set CROSSLY_CLIENT_ID (and CROSSLY_CLIENT_SECRET)
   __PM_DEV__              # http://localhost:3000
   ```

3. Click **Sign in with Crossly**, approve on Crossly's consent screen, and you land back on the app with your name
   and your latest listings.

## The flow, as Crossly documents it

| Step | Here |
|---|---|
| Discovery: `https://crossly.net/atlas/.well-known/openid-configuration` | `discover()` |
| Send the seller to `/atlas/oauth2/authorize` with `response_type=code`, `scope` including `openid` (and `offline_access` for a refresh token), `resource=https://crossly.net/api/v1`, `state`, and a PKCE `S256` `code_challenge` | `GET /login` → `authorizationUrl()` |
| Check `state` against this browser's cookie, and `iss` against the issuer (RFC 9207) | `GET /callback` |
| Exchange the code at `/atlas/oauth2/token` with the `code_verifier`; a confidential app authenticates with HTTP Basic (`client_secret_basic`), a public one sends only `client_id` | `exchangeCode()` |
| Who signed in: `/atlas/oauth2/userinfo` | `userInfo()` |
| Call the API with `Authorization: Bearer <access token>` (a JWT for `https://crossly.net/api/v1`) | `GET /v1/listings?limit=5` |
| Refresh before expiry with `grant_type=refresh_token`; refresh tokens **rotate**, keep the new one | `refreshTokens()` |
| Sign out: `/atlas/oauth2/revoke` | `POST /logout` |

Read [Authentication](https://crossly.net/docs/api-authentication) and [Scopes](https://crossly.net/docs/api-scopes)
for the full rules. `*`, `billing:write`, `payouts:write`, `funding:write`, `apps:read` and `apps:write` are never
granted to a third-party app, and some scopes need app review first (a `403` with `app_not_verified` or
`app_not_certified` tells you which).

## Before production

- **Sessions are in memory** and vanish on restart; tokens are kept server-side and the browser only holds an opaque,
  `HttpOnly` session cookie. Move sessions to your database or Redis, and encrypt refresh tokens at rest.
- Serve over **HTTPS** (cookies get `Secure` automatically when the redirect URI is https) and register the production
  redirect URI on the app.
- When the seller disconnects your app in Crossly, its tokens stop working at once and the webhooks it registered are
  deleted. Treat a `401` from the API as "signed out".
- **SDK note:** `@crossly/sdk` 0.2.0's `createClient({ pat })` only accepts tokens starting with `crossly_pat_` /
  `crossly_oat_`, and Atlas access tokens are JWTs (`eyJ…`), so this app calls the REST API with `fetch` directly.
